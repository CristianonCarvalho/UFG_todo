# Frontend React — Ciclo 3 — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar uma interface web simples em React (Vite) que consome a API de tarefas: criar, listar, filtrar por status, concluir, remover e editar a prioridade, exibindo as mensagens amigáveis da API.

**Architecture:** SPA em `frontend/`. Um módulo `api.js` concentra o `fetch` e converte erros no formato `{"erro": {...}}` em `ApiError`; o hook `useTasks` guarda o estado; componentes pequenos e sem estado de negócio compõem a tela. Em desenvolvimento, o Vite encaminha `/tasks` para a API (proxy), então o backend não muda.

**Tech Stack:** Vite 8.3.3, React 19.3.0, Vitest 5.0.3, React Testing Library, jsdom.

**Spec:** `docs/superpowers/specs/2026-10-06-frontend-design.md`.

## Global Constraints

- Todo o código do frontend fica em `frontend/`. Nenhum arquivo do backend (`app/`, `tests/`, `migrations/`) é alterado.
- JavaScript com JSX (sem TypeScript), CSS simples, sem bibliotecas além das listadas; versões fixadas com `=` exato (sem `^` nem `~`) e `package-lock.json` versionado.
- Interface e mensagens em português do Brasil. Os textos exatos abaixo devem ser usados como estão.
- Testes sem rede e sem backend: `fetch` é sempre falso. Nada de `window.confirm`.
- Comandos de qualidade, sempre a partir de `frontend/`: `npm test` e `npm run build`.
- Em worktree do Meister não há `node_modules`: rode `npm ci` em `frontend/` antes de testar (na Task 1, `npm install`, que gera o `package-lock.json`).
- Se o npm pedir um pacote omitido (por exemplo `@testing-library/dom`, peer do React Testing Library), adicione-o com versão exata e registre no relatório.
- Commits pequenos, Conventional Commits em português, com o trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Sem push.
- Fora do escopo: edição de título e descrição, paginação, autenticação, rotas de página, TypeScript, lint, CORS no backend, deploy, modo escuro, testes de ponta a ponta com navegador automatizado.

## Review Focus

1. Resposta 204 do `DELETE` e corpo vazio não podem quebrar o parse. (Task 2)
2. API fora do ar ou resposta fora do formato gera banner amigável, nunca tela branca. (Tasks 2 e 6)

```js
const NETWORK_MESSAGE =
  "Não foi possível conectar ao servidor. Verifique se a API está no ar e tente novamente.";
const GENERIC_MESSAGE = "Algo deu errado. Tente novamente em instantes.";

export class ApiError extends Error {
  constructor({ codigo = "ERRO", mensagem, detalhes = [], idRequisicao = null, status = 0 }) {
    super(mensagem);
    this.name = "ApiError";
    this.codigo = codigo;
    this.detalhes = detalhes;
    this.idRequisicao = idRequisicao;
    this.status = status;
  }
}

async function request(path, options = {}) {
  let response;
  try {
    response = await fetch(path, {
      ...options,
      headers: { "Content-Type": "application/json", ...options.headers },
    });
  } catch {
    throw new ApiError({ codigo: "SEM_CONEXAO", mensagem: NETWORK_MESSAGE });
  }

  if (response.status === 204) {
    return null;
  }

  let body = null;
  try {
    body = await response.json();
  } catch {
    body = null;
  }

  if (response.ok) {
    if (body === null) {
      throw new ApiError({ mensagem: GENERIC_MESSAGE, status: response.status });
    }
    return body;
  }

  const erro = body && body.erro;
  if (erro && typeof erro.mensagem === "string") {
    throw new ApiError({
      codigo: erro.codigo,
      mensagem: erro.mensagem,
      detalhes: Array.isArray(erro.detalhes) ? erro.detalhes : [],
      idRequisicao: erro.id_requisicao ?? null,
      status: response.status,
    });
  }
  throw new ApiError({ mensagem: GENERIC_MESSAGE, status: response.status });
}

export function listTasks(status) {
  const query = status === "pendente" || status === "concluida" ? `?status=${status}` : "";
  return request(`/tasks${query}`);
}

export function createTask({ title, description }) {
  const body = { title };
  if (description && description.trim()) {
    body.description = description;
  }
  return request("/tasks", { method: "POST", body: JSON.stringify(body) });
}

export function updateTask(id, changes) {
  return request(`/tasks/${id}`, { method: "PATCH", body: JSON.stringify(changes) });
}

export function completeTask(id) {
  return request(`/tasks/${id}/complete`, { method: "PATCH" });
}

export function deleteTask(id) {
  return request(`/tasks/${id}`, { method: "DELETE" });
}
```

```jsx
import { useState } from "react";

function fieldMessage(detalhes, campo) {
  return detalhes.find((detalhe) => detalhe.campo === campo)?.mensagem ?? null;
}

export default function TaskForm({ onSubmit }) {
  const [title, setTitle] = useState("");
  const [description, setDescription] = useState("");
  const [detalhes, setDetalhes] = useState([]);
  const [sending, setSending] = useState(false);

  async function handleSubmit(event) {
    event.preventDefault();
    setSending(true);
    const result = await onSubmit({ title, description });
    setSending(false);
    if (result.ok) {
      setTitle("");
      setDescription("");
      setDetalhes([]);
    } else {
      setDetalhes(result.detalhes);
    }
  }

  const titleError = fieldMessage(detalhes, "title");
  const descriptionError = fieldMessage(detalhes, "description");

  return (
    <form className="task-form" onSubmit={handleSubmit} noValidate>
      <div className="field">
        <label htmlFor="task-title">Título</label>
        <input
          id="task-title"
          value={title}
          maxLength={100}
          onChange={(event) => setTitle(event.target.value)}
          aria-invalid={Boolean(titleError)}
          aria-describedby={titleError ? "task-title-error" : undefined}
        />
        {titleError && (
          <p id="task-title-error" className="field-error">
            {titleError}
          </p>
        )}
      </div>
      <div className="field">
        <label htmlFor="task-description">Descrição</label>
        <textarea
          id="task-description"
          value={description}
          maxLength={500}
          rows={3}
          onChange={(event) => setDescription(event.target.value)}
          aria-invalid={Boolean(descriptionError)}
          aria-describedby={descriptionError ? "task-description-error" : undefined}
        />
        {descriptionError && (
          <p id="task-description-error" className="field-error">
            {descriptionError}
          </p>
        )}
      </div>
      <button type="submit" disabled={sending}>
        Adicionar
      </button>
    </form>
  );
}
```

```jsx
};
```

```jsx
          </button>
```

```js
import { useCallback, useEffect, useRef, useState } from "react";

import * as api from "./api.js";
import { ApiError } from "./api.js";

export function useTasks() {
  const [tasks, setTasks] = useState([]);
  const [filter, setFilter] = useState("todas");
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);
  const [busyIds, setBusyIds] = useState([]);
  const latestRequest = useRef(0);

  const load = useCallback(async (currentFilter, silent = false) => {
    const requestNumber = ++latestRequest.current;
    if (!silent) {
      setLoading(true);
    }
    try {
      const data = await api.listTasks(currentFilter);
      if (requestNumber === latestRequest.current) {
        setTasks(data);
      }
    } catch (caught) {
      if (requestNumber === latestRequest.current) {
        setError(caught);
      }
    } finally {
      if (requestNumber === latestRequest.current) {
        setLoading(false);
      }
    }
  }, []);

  useEffect(() => {
    load(filter);
  }, [filter, load]);

  const create = useCallback(
    async (data) => {
      setError(null);
      try {
        await api.createTask(data);
        await load(filter, true);
        return { ok: true, detalhes: [] };
      } catch (caught) {
        if (caught instanceof ApiError && caught.detalhes.length > 0) {
          return { ok: false, detalhes: caught.detalhes };
        }
        setError(caught);
        return { ok: false, detalhes: [] };
      }
    },
    [filter, load],
  );

  const act = useCallback(
    async (id, action) => {
      setError(null);
      setBusyIds((ids) => [...ids, id]);
      try {
        await action();
        await load(filter, true);
      } catch (caught) {
        setError(caught);
        await load(filter, true);
      } finally {
        setBusyIds((ids) => ids.filter((busyId) => busyId !== id));
      }
    },
    [filter, load],
  );

  const complete = useCallback((id) => act(id, () => api.completeTask(id)), [act]);
  const remove = useCallback((id) => act(id, () => api.deleteTask(id)), [act]);
  const changePriority = useCallback(
    (id, priority) => act(id, () => api.updateTask(id, { priority })),
    [act],
  );
  const clearError = useCallback(() => setError(null), []);

  return {
    tasks,
    filter,
    setFilter,
    loading,
    error,
    clearError,
    busyIds,
    create,
    complete,
    remove,
    changePriority,
  };
}
```

```markdown
## 16. Frontend em React com Vite, sem bibliotecas extras
- **Contexto:** a interface precisa ser leve e simples, e o spec já definia React.
- **Decisão:** Vite + React em JavaScript, CSS simples, estado com `useState` e `useEffect` encapsulados no hook `useTasks`; sem Redux, router nem bibliotecas de dados.
- **Motivo:** a tela é uma única página com poucas ações. Menos dependências significam menos manutenção.

## 17. Proxy do Vite em vez de CORS
- **Decisão:** em desenvolvimento, o Vite encaminha `/tasks` para a API; o backend não foi alterado e não tem CORS.
- **Motivo:** mantém o backend intacto. Servir o frontend em outra origem em produção exigirá `CORSMiddleware` ou um servidor de arquivos estáticos.

## 18. Um único módulo fala com a API
- **Decisão:** `api.js` concentra o `fetch`, trata o 204 do `DELETE` e converte o formato `{"erro": {...}}` em `ApiError`; falhas de rede e respostas fora do formato viram mensagens amigáveis.
- **Motivo:** os componentes não conhecem HTTP, e nenhum erro técnico chega ao usuário.

## 19. Sem estado otimista
- **Decisão:** depois de cada ação, o hook recarrega a lista do servidor e ignora respostas antigas quando o filtro muda rápido.
- **Motivo:** a tela sempre reflete o que a API tem, inclusive a origem da prioridade (`jev`, `fallback` ou `manual`).
```
